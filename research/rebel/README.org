#+TITLE: ReBeL — research stage (Kuhn/Leduc), validated before HUNL

Faithful implementation of ReBeL (Brown, Bakhtin, Lerer, Gong 2020,
arXiv:2007.13544) on the repo's exact-judge small games. Build target
=rebel=; see rebel.h for the faithfulness notes and the two documented
deviations (no policy-net warm start; unsafe test-time composition).

* Validation ladder (2026-07-04, this machine, CPU)

| test                                   | result                        |
|----------------------------------------+-------------------------------|
| kuhn exact (solver sanity, no leaves)  | expl 0.0056 → 0.00018 (T=1k)  |
| leduc exact-leaf CFR-D (decomposition) | expl ~0.10–0.12 (see below)   |
| leduc train, 20 epochs (full loop)     | expl 2.21 → 0.26–0.37, probe-MSE 0.062 → 0.012 |

* Findings worth remembering

1. *CFR-AVG is load-bearing.* Leaf beliefs from the CURRENT iterate
   (textbook CFR-D) diverge outright with a re-solved exact oracle
   (expl 1.6): continuation-equilibrium values jump discontinuously as
   the oscillating iterate moves the beliefs. Average-policy beliefs
   (the paper's CFR-AVG) converge. This reproduces the paper's stated
   motivation exactly.
2. *The unreached-subgame gap is real and grows with T.* As RM⁺
   sparsifies the trunk support, more round-boundary beliefs are
   zero-mass; their subgames are solved from uniform fallbacks and the
   best response farms them (expl rose 0.10→0.18 from T=1k→3k;
   REBEL_EVAL_SMOOTH=0.001 flattens it to 0.118→0.123). This is the
   classic unsafe-resolving cost — the safe-resolving gadget (Burch et
   al. 2014) is the known fix and the main open item.
3. *Per-query re-solved value oracles are WORSE than a trained net.*
   Sharpening the exact oracle (400→2000 inner iters) RAISED trunk
   exploitability (0.118→0.184): per-infostate values of a 2p0s
   subgame are not unique across equilibria, and sharper solves snap
   between selections as beliefs vary. A single trained v̂ is
   self-consistent by construction — the learned loop is expected to
   (and does) approach the composed floor. Don't use the exact mode as
   the quality bar; it's a mechanics smoke test.

* CUDA solver campaign (2026-07-09/10) — measured wins and negative results

=BatchRiverSolver= 11 → 53 targets/s (B=512, T=200), equivalence
maintained throughout (=gpu_check= f32 + f64 + graphed-vs-eager):
1. CUDA graphs (in-place state + capture/replay, bit-identical to eager):
   NECESSARY but not sufficient — the "launch-bound" diagnosis was stale;
   the solver was KERNEL-bound in the dense [B,n,52] showdown cumsum.
2. Sparse per-card showdown (card-restricted prefix sums [B,52,51] +
   constant boundary indices): 4.7× — the real win.
3. NEGATIVE: level-synchronized flattening (one actor per depth, whole
   levels per kernel, ~7× fewer launches) measured 33.7/s vs 52.7/s —
   after the sparse fix the solver is memory-bound, and level-sync ADDS
   traffic (both players' reaches materialized at every edge, per-node
   value buffers, index ops). Reverted; f64 trajectory agreement was
   incidentally 5× better (mean 2e-6), confirming the arithmetic.
   Also: two 6.6/36-targets/s scares were CONTAMINATED benches (a
   forgotten concurrent 8k-target run) — kill stray GPU jobs before
   benchmarking.
4. B-scaling INVERTED: B=2048 → 37/s (past the L2 knee); B=512 optimal.
5. Deployment: REBEL_GPU_BATCH now PIPELINES (GPU thread + own spec
   builders, REBEL_GPU_FRAC share) concurrent with the CPU pool — but on
   this 20-core box the gain is ~5-10% (core contention eats it; CPU pool
   alone ≈ 110 targets/s vs GPU 43-53/s incl. per-epoch capture). Verdict:
   for river data generation on THIS box, CPU workers remain fine; the
   graphed solver's real targets are GPU-rich/CPU-poor hardware (compute
   VM), play-time re-solving, and future turn-tree GPU solves where net
   leaf batching already lives on the device.
6. PERSISTENT KERNEL (=hunl_fused=, "rebel hunl 22"): the whole
   T-iteration solve as ONE kernel launch, one block per subgame, NVRTC
   runtime-compiled (no nvcc; dlopen'd nvrtc + driver API). Validated
   fused-vs-CPU mean 3.9e-5 / max 1.4e-2 (mean = arithmetic honesty, max
   = RM⁺ selection spread; fold atomics ⇒ nondeterministic runs).
   Measured 55.9/s @B=512 (parity with graphs), 62/s @B=2048-8192 (fixes
   the torch batch inversion, zero capture overhead). CONCLUSION, now
   confirmed across three architectures: n=1326 river CFR is
   LATENCY-bound on per-depth recursion state (depth×A×n > shared memory
   → local memory), which CPU caches handle natively — ~55-60/s is this
   GPU's level however the kernel is organized. The fused path is
   solve()'s default (REBEL_NO_FUSED opts out); its value is large-B,
   weaker-CPU hosts, and wider action abstractions.

* Gen-3 rental hardening (2026-07-22)

The dataset format is now v3. Both players' ranges are normalized over
board-compatible combos at the shared feature boundary (including fused-GPU
leaf queries), and private hands are sampled from the compatible joint
distribution. Linear-CFR root values and continuation iterations use weight
=t=; the benchmark-selected PCFR+ variant uses =t^2=. The sampled public path
uses the selected current iterate while its returned CFR-AVG PBS uses average
reaches. Old v1/v2 rows are intentionally rejected: their range or target
semantics differ, so do not combine or resume them.

The 4x5090 launcher defaults to 5M turn + 500k river + about 37.5k flop rows.
It uses collision-free absolute-row seeds, three pure fused-GPU lanes plus one
CPU lane, a verified transactional mix, a 5.6M replay cap, and a 500k device
cache whose slab admissions cycle without replacement. GPU batches sample
with replacement within each random cache slab; the persistent shuffled slab
order exposes the whole replay about every 11 epochs. In-memory masks are u8,
making a packed
row 40,008 bytes and the default mixed replay about 206 GiB of payload. Offline
loading uses a uniform reservoir per street (2%, capped at 2,048/street)
across the whole mix. Validation reports every street and checkpoint
selection minimizes macro normalized MSE, so rare flop roots can veto a
turn-only improvement. Validation is measured after each update; the best
checkpoint is published via atomic rename. =tools/rebel_rental_probe.sh= must pass on the
rental before =tools/vm_gen3_test.sh= (which launches the full campaign after
its toy smoke). The preflight is fail-closed on fused execution, CPU/GPU value
masks, exported play strategy layout, and every GPU's PCFR+ result.

The fixed v3 row file is now mapped read-only with =REBEL_MMAP_DATA=1=.
Training retains only 64-bit row indices plus the small heldout copy: no
millions of vector allocations and concurrent architecture arms share the
Linux page cache instead of copying the 206-GiB corpus. Gen-3 trains the base
and spec arms concurrently on separate GPUs. DDP remains a later, measured
optimization: LibTorch C++ has no frontend DDP wrapper, 5090s have no NVLink,
and the 42-MB baseline / 105-MB spec gradients would reduce over PCIe every
step. The mmap prerequisite is now in place without putting unvalidated c10d
logic on the paid run's critical path.

After the paired analytic-LBR gates choose an arm, Gen-3 runs =train_root=
with that selected model as its own oracle, fine-tuning against the real
preflop→flop query distribution while retaining the mapped mixed replay. A
paired champion tolerance is enforced; gadget soundness, early all-in
responses, pot-pressure and shove probes are separate campaign gates.

* Competitive play protocol

=rebel_hunl play_server= is a line protocol for integrating the re-solving
agent with a poker client. Set =REBEL_CKPT= and the checkpoint architecture
variables, then send:

- =start <hero-seat> <hole0> <hole1>= (card ids 0..51)
- =board <c0> <c1> <c2> [turn] [river]= after the engine changes street
- =step <action-index>= for an observed action by either seat
- =act= when =current_player= is the hero; the JSON reply contains the action
  and solve latency
- =bench <hands>= for p50/p95/max latency by street on internal self-play

The server validates card collisions, action legality, turn ownership and
board synchronization. State replies include the currently legal indices;
index 0 is fold, 1 check/call, 2..12 the configured pot fractions, and 13
all-in. It uses sparse ={fold, call/check, pot, all-in}=
continuations by default, matching target generation; half-pot river is an
explicit =REBEL_RIVER_HALF_POT= experiment. This is fixed 100bb HUNL only—no
rake, ICM, multiway pots or arbitrary stack-depth translation.

* HUNL port map (stage 2)

- Beliefs/ranges: LBR's =Belief= (src/lbr.cpp) already Bayes-tracks
  1326-combo ranges — reuse for the PBS tracker.
- Subgame solver: this solver's structure, vectorized over 1326 hands
  on GPU tensors; terminal fold eval O(n) via the sum-minus-blockers
  trick; showdown eval O(n·52) via rank-sort sweep (Game/Utility
  RangeEquity/HandStrength kernels are the starting point).
- Depth limit: current street; river subgames solve to terminal
  (exact, no net) — mirrors round-2 here.
